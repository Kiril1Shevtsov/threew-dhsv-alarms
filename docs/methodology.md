# Протокол эксперимента

## Данные

Версия 3W 2.0.0, commit `914af287b1cf3e5207dce0da1e9dc08361c9adeb`.

Выборка разработки: все 22 реальные DHSV-записи выбранной ревизии и 23 записи нормального режима; всего 13 скважин. Для извлечения признаков применяется 180-секундное окно с шагом 15 с после первого часа. Метки, идентификаторы скважин и момент отказа не включены в признаки. Разметка используется только для обучения и оценки.

Внешний цикл исключает целую скважину. Внутри обучающей части GroupKFold с тремя частями формирует прогнозы для выбора порога. Для исходного эксперимента сохранённые внешние прогнозы того же классификатора и тех же 45 записей были использованы повторно; внутренние модели обучены для настройки порога. Это разработочный эксперимент, а не новый нетронутый подтверждающий набор.

Дополнительный набор содержит 15 записей из 15 скважин, не пересекающихся с разработкой. Выбирались классы 5, 7 и 9, файлы размером <1 МБ, по минимальному Git blob SHA на скважину. Выбор и окончательные модели/пороги зафиксированы до вычисления результатов этого набора. В нём присутствуют только нормальные участки и другие типы отказов, без DHSV-положительных событий. Метрики для этих двух задач публикуются раздельно.

## Модели и признаки

Random Forest: 200 деревьев, minimum leaf size 5, `max_features=sqrt`, сбалансированные классы. HistGradientBoosting: 150 итераций, до 15 листьев, learning rate 0,1, L2 1,0. Seed: 20261109.

Для каждого датчика: среднее, стандартное отклонение, минимум, максимум, последнее значение, изменение за окно и доля пропусков. Вариант `calibrated` в именах означает **нормировку датчиков**, а не вероятностную калибровку. Пропуски заполняет медиана обучающей части, дополнительные индикаторы пропусков включены. Нормировка первого часа вычисляется без его меток, прогнозы начинаются позже этого часа.

## Событийная политика

Три последовательных превышения с шагом 15 с подтверждают тревогу. Ложный эпизод — непрерывный участок подтверждённой тревоги в размеченной норме внутри одной записи. «Обнаружение за 300 с» отсчитывается от начала перехода в положительную метку, а не означает предсказание за 300 с до события.

«Чистое обнаружение» дополнительно требует отсутствия ложных эпизодов во всей записи (включая участки после события), как определено метрикой `clean_300`. Задержка для записи, начинающейся уже в отказе, не приравнивается ко времени с начала файла: такой старт считается цензурированным. Раздельно сохраняется любое срабатывание во время другого отказа.

Сравниваются порог 0,5, порог на основе 99-го процентиля отрицательных оценок и событийная настройка с бюджетом 1, 2 или 6 ложных эпизодов в сутки и долей нормального времени под тревогой ≤1%. Среди допустимых кандидатов максимизируется число чистых обнаружений за 300 с, затем обычных; далее минимизируются ложные эпизоды и выбирается больший порог. Порог выше 1 отключает тревогу, а не означает успех детектора.

## Воспроизводимость

`data/development_features.npz` содержит матрицы признаков `raw` и `calibrated`; порядок строк соответствует `data/development.csv`. `data/thresholds.csv` содержит внешний порог для каждой модели, политики и исключённой скважины. `data/splits.json` описывает внутренние разбиения. `models/` содержит окончательные модели, обученные на разработочной выборке; варианты `original_*` являются контролями, обученными только на 22 DHSV-записях.

`check_results.py` пересчитывает событийные таблицы из прогнозов. `predict.py` применяет сохранённые модели к исходному Parquet. `train.py` заново выполняет вложенный цикл для HGB; в отличие от исходного расчёта, он сам пересчитывает внешние прогнозы. Повторное обучение не использует дополнительный набор для настройки. Модели RF включены в готовом виде; скрипта их повторного обучения нет.

Полный исторический набор содержит коррелированные окна. Их нельзя считать независимыми испытаниями для доверительных интервалов. Историческая интерполяция до 1 Гц не устанавливает фактическую задержку поступления датчиков в промышленной системе.
